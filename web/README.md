# JobPilot — MVP

Лендинг, четырёхшаговый онбординг и рабочий кабинет поиска вакансий на русском языке. Фирменный знак — белый радар на красном фоне.

## Что работает

- `/` — лендинг с переходами к продукту и онбордингу.
- `/onboarding` — цель поиска, условия, навыки и текст резюме; импорт `.txt`, текстового PDF и DOCX с проверкой извлечённого текста.
- `/app` — личный кабинет: поиск вакансий hh.ru с пагинацией, сохранение, разбор требований с цитатами из профиля, AI-документы с просмотром отличий и трекер.
- `/app?demo=1` — отдельный демонстрационный режим; изменения в нём не сохраняются после перезагрузки.
- `/api/state` — хранение профиля, вакансий, откликов и документов в Supabase с привязкой к пользователю.
- `/api/jobs/search` и `/api/jobs/[id]` — серверная интеграция с HeadHunter API.
- `/api/ai` — защищённая серверная интеграция с OpenRouter для разбора вакансии, письма и адаптации резюме.
- `/api/account` — подтверждаемое удаление аккаунта и рабочих данных.

Для входа используется Supabase Auth: email/password, Google и GitHub. API проверяет подписанные claims на сервере; ID владельца никогда не принимается из тела запроса. RLS ограничивает каждую запись её владельцем. Сохранение использует версию записи и отклоняет конфликтующие изменения из другой вкладки.

## Границы MVP

Демо-вакансии доступны только в отдельном `/app?demo=1`. В обычном кабинете вакансии приходят из HeadHunter API и сохраняются в Supabase. OpenRouter создаёт AI-разбор, сопроводительное письмо и адаптированный текст резюме. Цитаты для подтверждённых требований проверяются кодом, но пользователь всё равно должен проверить документы на фактические ошибки. Сканированные PDF без текстового слоя не поддерживаются. Платежей нет.

Автоотклик включается отдельно в `/app?view=agent`: соискатель подключает hh.ru через OAuth, выбирает резюме и задаёт лимит до пяти откликов за сутки, зарплату и исключённые компании. Ежедневно в 08:00 UTC агент ищет вакансии, открывает их подробности, проверяет роль, формат, навыки и работодателя, составляет письмо только из профиля и отправляет через `POST /negotiations`. Журнал показывает подтверждённые, пропущенные и требующие проверки попытки. Задачи с тестами и неясными ответами hh.ru не повторяются автоматически. Ручная смена статуса в трекере по-прежнему не отправляет отклик.

## Разработка

Node.js 22.13+, pnpm (версия зафиксирована в `package.json`).

```bash
pnpm install --frozen-lockfile
pnpm dev
pnpm build
```

Сайт работает на Next.js 16 и Vercel. Данные хранятся в таблице `public.workspaces` проекта Supabase; на таблице включён RLS. Переменные окружения перечислены в `.env.example`.

Чтобы включить живой поиск, зарегистрируйте приложение на `dev.hh.ru` и добавьте `HH_CLIENT_ID` и `HH_CLIENT_SECRET` в Vercel. Чтобы включить AI-функции, добавьте серверные `OPENROUTER_API_KEY`, `SUPABASE_SECRET_KEY` и выберите модель в `OPENROUTER_MODEL`. Для автоотклика также зарегистрируйте OAuth redirect URI из `.env.example`, задайте `AGENT_ENCRYPTION_KEY` и `CRON_SECRET` как серверные секреты Vercel и примените миграцию `agent_auto_apply`. Секрет Supabase нужен для лимитов и серверных настроек агента; никогда не используйте префикс `NEXT_PUBLIC_` для этих ключей. Текст профиля и вакансии передаётся OpenRouter при запуске AI-функции; агент использует локальный шаблон письма без AI-запроса.

Перед развёртыванием примените миграции из `../supabase/migrations/`: они создают политику RLS для `workspaces` на свежем проекте, учёт AI-запросов, серверные настройки агента, журнал и атомарное резервирование откликов. На существующем JobPilot-проекте четыре политики `workspaces` уже настроены и сохраняются. Миграции не применяются при сборке Next.js.

## Проверка

```bash
pnpm exec tsc --noEmit
pnpm test
pnpm build
```

Проверяются сопоставление навыков, цитаты для AI-разбора, валидация ссылок и зарплат, нормализация ответа hh.ru, очистка HTML и наличие защиты API. Для настоящей проверки доступа двух пользователей к базе запустите `node scripts/verify-rls.mjs` на отдельном staging-проекте с `RLS_TEST_ALLOW_WRITE=1`, `RLS_TEST_PROJECT_URL`, `RLS_TEST_PUBLISHABLE_KEY` и `SUPABASE_SECRET_KEY`. Скрипт создаёт и удаляет две временные учётные записи. Тест не выполняется на неактивном проекте Supabase.

WebMCP при поддержке браузером предоставляет чтение соответствий и открытие разбора вакансии. Проверка в поддерживающем WebMCP браузерном контексте не выполнялась.
